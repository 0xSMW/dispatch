# Changelog

## Unreleased

- Add signup-form management and safe credential-free HTML/fetch snippets under Audience, Forms. Enforce verified senders, declared properties/live topics, exact origins, 16 KB bodies, honeypot/IP limits, rolling address/form cooldowns and configurable tenant UTC daily caps. Pending consent is not receiving. Seven-day purpose/scoped confirmation links only grant consent on deliberate POST, with transactional single-use state, explicit revival, once-only topic transitions and configured HTTPS redirects. Viewer email/log output hides confirmation links.
- Prepare encrypted inbound integration management with hash-only one-time/rotated URL tokens and credential-free bounded delivery reads. Signed receiver activation remains a separate integration package.

- Add SQL-backed dynamic segment filters, recipient-aware real email engagement, live preview, cached detail counts, and dynamic contact context/broadcast snapshots. Reuse the typed rule editor and expose filter/null conversion in the API and three SDKs. Refuse dynamic membership writes and guard conversions with segment row locks. Valid finite numeric/ISO values are supported; universal JavaScript legacy parsing is not promised.
- Hold static-segment locks through import creation, recheck dynamic targets before automation contact writes or deleted-contact skips, preserve same-second filter revisions in count caching, and use current detail type for membership timestamps after conversion.

- Install six lifecycle presets atomically with a verified sender through `/template-library/automations/{slug}/install`, the three SDKs, CLI, and dashboard. Reuse existing templates without overwriting or publishing them; create only missing compatible dependencies and a disabled automation. Newsletter welcome requires a live tenant topic at installation; other Marketing flows may install disabled without one but cannot be enabled until configured. Restore one flat menu in its original order and make Canvas the default automation workspace with compact overlay controls and a dismissible inspector. Add event firing counts, stage previews, six public recipes and multilingual examples. Transactional sending needs no lifecycle setup.
- Add visible API reference buttons with cURL, TypeScript, Python, Go and Agent tabs. Generate public-only `llms.txt` and `llms-full.txt` with `pnpm llms`; only explicitly approved, Git-tracked public guides are included.
- Accept declared hyphenated automation mappings without weakening own-property traversal, and return validation errors for missing-trigger graphs. Classify reserved unsubscribe inline defaults consistently as Marketing and retain known Marketing intent across template version edits without restoring library provenance. Contact timelines expose stored nullable terminal exit reasons beside the existing state and run link.
- Keep automation loop depth tied to original enrollment across paused trigger edits. Caller payload depth, including legacy real `@` events, is never trusted. Supported event-only installations upgrade their existing runs at known root depth zero, preserving their steps, keys and waits. Genuinely ambiguous mixed-era runs retain unknown depth: mutations without eligible internal triggers continue, while matching triggers fail explicitly and roll back rather than guessing or restarting runs. Recover supported contact-dispatch/executor/Stop deadlocks by retrying only complete, rolled-back affected operations; exhausted executor attempts remain retryable without failed steps or reviving stopped runs.
- Record imported effective topic opt-outs as well as opt-ins in contact history, regardless of the resolved automation-trigger flag. A combined global and selected-topic opt-out compares original consent with final saved preferences and records both changes once. Only selected topics gain history; subscription counts and topic enrollment remain opt-in only, and repeat/no-op imports add no transitions.
- Make Transactional and Marketing explicit in automation Send email steps, template lists and the library; broadcasts are always Marketing. Send-step configs store and return `kind`, while legacy input without it is still inferred from `topic_id`. Transactional cannot have a topic or use a Marketing template. Disabled or paused Marketing drafts may wait for a topic, but creating enabled, enabling, or resuming returns 422 without a live topic; execution never falls back to Transactional if that topic is missing or deleted. All SDKs support the optional input kind. Ordinary `/emails`, batches, SMTP, and SDK `emails.send` gain no field or setup requirement, and their delivery behavior is unchanged.
- Add Exit, Filter, and ordered multi-way Branch automation steps across the API, SDKs, and editors. Branches support 2–10 uniquely keyed paths plus Otherwise, with first-match routing and recorded choices. Filters test once or guard every following step against fresh contact state, including resumed waits; failure ends the run without a default fallback. Runs expose saved guards and nullable `exit_reason` (`completed`, `exit`, `filter`, `stopped`, or `stranded`); lifecycle webhooks include the reason, with null for started and failed runs. Existing statuses, triggers, pause/version behavior, and stable step keys are unchanged.
- Add atomic paused automation editing and non-mutating stranded-run previews through `PATCH /automations/{id}?dry_run=true`, distinct SDK preview methods, and CLI `automations update --dry-run`. Stable step keys keep runs in place; removed next keys stop affected runs with `Its next step was removed or changed while the automation was paused` and cancel their waiting step rows. Saved keys permanently reserve their original step type: reuse with a different type returns 409, so replacements need a new key. Existing delays and event waits keep their stored config, matching rules, and timeouts; later arrivals use the edits. First paused edits convert legacy index keys to explicit keys. Dashboard Pause/Resume controls, editable paused builders, stranded-run confirmation, and the Stop re-entry reset are available. Transactional sends are unchanged.
- Add API and CLI pause/resume for automations, with enabled/paused/disabled statuses and read-only graph versions in all SDKs. Pausing holds existing runs and enrollment jobs without cancelling them; event waits, current contact updates, and history continue, and timers retain their due times. Resume uses fresh contact state and never replays missed triggers. Per-step version guards hold stale graphs for a fresh load. Stop clears pause and cancels runs. Creating paused is rejected, and pausing disabled returns 409; legacy enabled booleans still map to enabled/disabled. Dashboard lists and headers show paused status.
- Add explicit asynchronous enrollment of existing live contacts into enabled, unpaused contact automations, for one segment or all contacts. Jobs page 500 contacts using current snapshots, ignore Contact changes From/To filters, process each contact once per job, and preserve lifetime once re-entry without changing contact history. API, CLI, and SDKs expose job counts and cancellation between batches; cancelling enrollment or a contact import does not cancel runs already created. Claim normal runs before bulk runs, with at most two runs per automation per tick, and prune contact-change history in bounded batches using `CONTACT_CHANGES_RETENTION_DAYS` (default 400).
- Add once-per-contact re-entry, defaulting new contact-triggered automations to `once` and event-triggered automations to `every_time`; existing automations keep `every_time`. Trigger edits preserve the chosen rule. Contact deletion clears once enrollments, and revival can enter again. Stop optionally resets only once enrollments for contacts whose active runs it actually cancels; completed runs keep theirs.
- Let contact imports start matching enabled Contact added, Subscribed to topic, and Added to segment automations, but not Contact changes. This defaults off; an explicit per-import boolean overrides the tenant default, which is resolved and stored at creation. Import runs have bulk priority, retries do not repeat applied transitions, and enabling triggers does not clear opt-outs. Matching flows may send immediately or after configured waits. Import responses expose the stored flag, and SDK import and stop options preserve omission and explicit `false`. Transactional send requirements are unchanged.
- Add contact-added, contact-change, topic-subscription and static-segment triggers alongside existing event triggers. Match typed From/To changes, ignore no-ops, and record transactional contact history even without a matching flow. Separate internal events from app events, prevent step self-entry and stop trigger chains at depth five. API, CLI, SDKs and both automation editors use the same five trigger shapes.
- Add Boolean and Date contact properties with typed fallbacks and CSV imports. Dates stay ISO strings; boolean property cells accept true/false, yes/no, and 1/0. Invalid nonempty boolean/date cells now fail the row instead of silently becoming false or text. Undeclared keys remain allowed.
- Add fresh topic/static-segment membership and recorded event time to automation context, plus `not_contains`, `within`, and `not_within` rules and typed field pickers. Reserve `topics` and `segments` for new property definitions while preserving live legacy definitions and values.
- Add optional `send_email.variable_mapping` for dotted event/contact fields. Existing template variables remain literal, automatic event payload variables still work, and recipient and unsubscribe context stays protected. Transactional send requirements are unchanged.

- Clarify topic subscriptions, static segments, event-created contacts, delay examples and canvas endings. Link Suppressions from Audience as well as Emails. Stop confirmation shows the current count and warns that every run in progress is cancelled, not paused.
- Download a domain's actual DNS records as a BIND zone file for import into DNS hosts other than Route 53, including from a viewer session.
- Keep canvas step and ending buttons clickable inside React Flow's non-selectable wrappers.

- Show Required/Optional template variable controls with saved fallbacks, keep lists fixed Required, and add a visual placeholder panel for names, requirements, fallbacks, and list-item scope. The stored variable model and rendering rules are unchanged.
- Keep each visual list-item fallback when its inspector is dismissed and reopened. Preserve literal inline defaults, including ampersands, quotes, angle brackets, and entity-looking text, through visual saves and reloads.
- Reject unsafe raw HTML in visual paste and drop, including positioned markup inside placeholder fallbacks, without replacing the selection.
